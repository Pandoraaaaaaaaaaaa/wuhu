## 子问题 2：语言与解释器层面有哪些主要新特性？

官方文档列出的解释器相关改进如下 [3]：

- **PEP 810 显式惰性导入**：新增 `lazy` 软关键字，可写作 `lazy import x` 或 `lazy from x import y`，模块在名称首次被使用时才真正加载，目的是降低启动时间。可通过 `-X lazy_imports` 选项、`PYTHON_LAZY_IMPORTS` 环境变量或 `sys.set_lazy_imports()` 全局控制，也可用 `sys.set_lazy_imports_filter()` 做选择性控制。`lazy` 仅允许出现在模块作用域，在函数、类体或 try/except/finally 中使用会引发 `SyntaxError`；星号导入和 `__future__` 导入也不能是 lazy。
- **PEP 814 `frozendict`**：新增内置不可变映射类型。它不是 `dict` 的子类，在键和值都可哈希时本身可哈希，保留插入顺序但比较时不考虑顺序。`copy`、`json`、`pickle`、`pprint` 等多个标准库模块已支持它。
- **PEP 661 `sentinel`**：新增内置类型，用于创建具有简洁表示的唯一哨兵值，复制时保持同一性，支持与 `|` 组合用于类型表达式。
- **PEP 686**：默认编码改为 UTF-8。
- **PEP 798**：支持在推导式中使用解包。
- **PEP 829**：包启动配置文件。
- **实验性 JIT 编译器**得到显著升级，同时错误信息有所改进。

## 子问题 3：标准库、类型系统、C API 与构建/发布方面有哪些变化？

- **标准库**：新增 `profiling` 包（PEP 799），将 `profiling.tracing`（由 `cProfile` 迁移而来的确定性追踪）和 `profiling.sampling`（新的统计采样分析器 Tachyon）统一在一个命名空间下。`cProfile` 保留为别名以保持兼容，`profile` 模块已被弃用，计划在 3.17 移除。此外命令行输出增加了更多颜色，并新增 `math.integer` 模块 [3]。
- **类型系统**：新增 PEP 728（带类型额外项的 `TypedDict`）、PEP 747（`TypeForm`）和 PEP 800（类型系统中的不相交基类）[3]。
- **C API**：新增 PEP 782（`PyBytesWriter`）、PEP 788（防止解释器终结期间的 C API 问题），以及 PEP 803/820/793（面向自由线程构建的稳定 ABI 及相关 C API）[3]。
- **构建与发布**：PEP 831 默认启用帧指针以改善系统级可观测性；官方 Windows 64 位二进制改用 tail-calling 解释器；官方 macOS 二进制默认安装自由线程支持 [3]。
